# Cell Machine

**Cell Machine** 是一种有限、持续、可组合的最小计算单元。它不是一台被缩小的通用计算机，而是构成更大计算系统的可复用“计算细胞”。

它直接受到著名极简语言 [Brainfuck](https://en.wikipedia.org/wiki/Brainfuck) 的启发：保留程序指针、数据指针、当前单元操作和极少符号指令，同时主动放弃无限纸带，将抽象图灵机收敛成一台诚实、闭合、适合物理实现的有限机器。

> Brainfuck 展示了极少规则足以表达计算；Cell Machine 探索极少物理状态如何组成计算系统。

当前版本是 **0.0.1 参数化概念验证规范**。

## 一分钟理解

一台 Cell Machine 只有：

- `2^A` 个统一内存 Cell；
- A 位程序指针 `PP` 和数据指针 `DP`；
- 可寻址 `2^A` 个逻辑 I/O 端口编号；
- 固定4位 opcode，恰好编码16条核心指令；
- A 位 operand 和 `A+4` 位机器字。

复位时：

```text
PP = 0
DP = 0
```

程序通常用第一条指令将 DP 移出程序区。下面是 `A=8` 的常见写法：

```cell
>80
```

PP 和 DP 访问同一片内存，指针也可以成为普通数据：

```cell
P       # memory[DP] ← PP
D01     # memory[DP+1] ← DP
@       # PP ← low_A(memory[DP])
```

Cell 没有停机指令，也没有“程序结束”。地址自然模 `2^A` 环绕；全部16种 opcode 均有定义，全零机器字 `>0` 自然充当 NOP。程序可以进入固定点，但只要环境继续提供执行周期，取指和执行就不会在架构层停止。

## 为什么有限反而更简单

```text
opcode宽度     = 4 bit
参数/地址宽度  = A bit
PP / DP        = A bit
地址数量       = 2^A
内存字宽度     = 指令宽度 = A+4 bit
逻辑端口数量   = 2^A
```

这种对称性意味着：

- 一个参数覆盖整个地址空间；
- 没有长跳转、扩展地址和跳板；
- 没有越界和未对齐访问；
- 不需要运行时括号扫描或循环栈；
- 完整 Cell 状态很容易保存、复制、迁移和观察；
- 任意 `A+4` 位机器字都具有安全、确定的行为。

常用规格形成同一语义的处理器家族：

```text
CM-4+4   = 16 × 8-bit Cell
CM-4+5   = 32 × 9-bit Cell
CM-4+6   = 64 × 10-bit Cell
CM-4+7   = 128 × 11-bit Cell
CM-4+8   = 256 × 12-bit Cell
CM-4+10  = 1024 × 14-bit Cell
CM-4+12  = 4096 × 16-bit Cell
```

增加 A 会同时扩大程序、数据和端口空间，使大型程序成为可能，而不增加新的指令或架构状态。

## 指令概览

| 类别       | 指令           | 含义                            |
| ---------- | -------------- | ------------------------------- |
| 数据指针   | `>n` `<n`      | DP 相对右移或左移               |
| 数据       | `+n` `-n` `=n` | 当前字加、减或赋值              |
| 相对控制流 | `[n` `]n` `:n` | JZ、JNZ、JMP                    |
| 绝对控制流 | `(n` `)n` `;n` | JZ、JNZ、JMP                    |
| 指针反射   | `Pn` `Dn`      | 将 PP 或 DP 写入 `memory[DP+n]` |
| 间接控制流 | `@n`           | `PP ← low_A(memory[DP+n])`      |
| I/O        | `,n` `.n`      | 从端口读取、向端口写出          |
| 源码       | `#`            | 注释到行末，不生成指令          |

条件括号有两种清晰模式：

- 无参数 `[]` 由编译器成对匹配并填写相对偏移；
- 无参数 `()` 由编译器成对匹配并填写绝对地址；
- `*` 由编译器展开为目标规格的全一 operand，因此 `:*` 是跨地址位宽的固定点自循环；
- 显式参数的 `[n ]n (n )n` 是完整、独立的条件跳转，不参与配对；
- 无参数形式必须正确嵌套，不能与显式形式混合组成一对。

因此 `[]` 与 `()` 在使用方式上完全对称，只在地址表示上分别选择相对与绝对。括号栈只存在于编译器中，运行时和硬件都不需要扫描或配对。

完整语义见 [docs/specification.md](docs/specification.md)。

## 立即运行

直接用浏览器打开：

```text
web/index.html
```

网页包含：

- 编译、复位、运行、外部暂停和单步；
- 可分页的参数化统一内存视图；
- 可在运行中切换的 `1–4096 IPS` 二次幂目标执行速率，并显示浏览器实测 IPS；
- PP、DP 和当前字观察；
- 字符端口与数值端口；
- 直接编辑任意完整机器字；
- 自动括号回填和错误提示。

地址位宽可以选择 `4、5、6、7、8、10、12`。网页会按目标容量和 operand 范围提供可直接运行的示例；每个内存分页最多显示为一个 `16×16` 观察口。

解释器的“暂停”只属于外部宿主，不是 Cell 指令或架构状态。

下面的核心动作在 `A=8` 机器的空白数据单元中生成紧凑机器字 `A10`，也就是绝对跳转 `;10`。随后保存动态代码入口 `80` 并间接执行：

```cell
>80 =00
+* +* +* +* +* +* +* +* +* +* +1A

```

## 设计目标

1. **简单可读**：一页规范可以解释整个核心。
2. **硬件友好**：窄指针、固定字宽、少状态、无异常和无运行时括号扫描。
3. **执行透明**：源码指令直接对应机器字，不隐藏昂贵操作。
4. **持续存在**：没有停机、结束或非法执行状态。
5. **全定义**：16种 opcode 全部有定义，全零字是 NOP，所有地址和算术自然环绕。
6. **开放交互**：端口连接字符流、GPIO、传感器、邻居 Cell 或游戏世界。
7. **代码数据同构**：程序可以检查、修改、生成和执行程序。
8. **可组合**：复杂性来自复制、连接和时间演化，而不是让单个 Core 无限膨胀。

## 适合什么

- FPGA/ASIC 中的微型控制核和可编程状态机；
- 确定性信号源、灯光、音乐与互动装置；
- 游戏中的可编程物体、机器人、工厂和数字生物；
- 元胞自动机、人工生命和自修改程序实验；
- 大量 Cell 组成的局部消息传递阵列；
- 计算机体系结构和语言设计教学。

它不试图取代大型 MCU、操作系统或高性能数值处理器。

## 多 Cell

每个 Cell 保持本地状态，通过端口互连，不要求共享内存或缓存一致性：

```text
┌────────┐       ┌────────┐       ┌────────┐
│ Cell A │──────▶│ Cell B │──────▶│ Cell C │
│ 2^A字  │◀──────│ 2^A字  │◀──────│ 2^A字  │
└────────┘       └────────┘       └────────┘
```

阵列可以采用网格、环、树、流水线或游戏定义的任意拓扑。I/O 是核心与外设、邻居以及管理环境之间唯一必要的组合边界。

## 编译器边界

编译器可以承担能够改善可读性或硬件效率的工作：

- 空白与 `#` 注释；
- 默认参数；
- `*` 全一 operand 展开；
- `[]` 相对回填；
- `()` 绝对回填；
- operand 范围、括号和 `2^A` 条指令上限检查。

核心编译器暂不提供标签、变量、宏、函数、类型或链接器。原则是：编译器可以帮助人准确表达已有机器语义，但不悄悄引入新的语言抽象。

## 思想谱系

Cell Machine 明确致敬和参考：

- Brainfuck 的双指针、当前单元与极简符号哲学；
- [Self-modifying Brainfuck](https://soulsphere.org/hacks/smbf/) 的代码数据统一探索；
- Core War、Tierra、Avida 等有限机器和数字生命实验；
- GreenArrays GA144、简单处理器阵列和可编程状态机的组合思想。

这些方向分别已有丰富先例。Cell Machine 的目标是把它们收敛成一个有限、对称、可直接在网页与硬件中复用的计算细胞。

## 状态

这是一个仍在形成中的架构提案。0.0.1 版固定16条核心指令和 `4+A` 参数化机器字，并通过网页解释器、示例与 Logisim 原型验证统一内存、指针反射、间接控制流和可变地址空间。后续工作包括进一步简化硬件拓扑、探索 Cell 阵列互连以及实现独立编译器。
