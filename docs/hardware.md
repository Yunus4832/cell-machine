# 硬件实现建议

仓库中的 [`hardware/logisim/cell-machine-4+8.circ`](../hardware/logisim/cell-machine-4+8.circ) 是 **CM-4+8**（4 位 opcode、8 位 operand、12 位机器字、256 个存储单元）的 Logisim 2.7.1 示例实现，而不是所有地址位宽共享的固定电路。其他规格沿用相同指令与数据通路结构，但需要按参数位宽调整 PP、DP、RAM、机器字和相关算术器件。

## 最小数据通路

```text
                  ┌────────────────────┐
          PP ────▶│                    │
                  │ 2^A × (A+4) memory │
          DP ────▶│                    │
                  └─────────┬──────────┘
                            │ instruction / data
                     ┌──────▼──────┐
                     │ decoder/ALU │
                     └──────┬──────┘
                            │
                     ┌──────▼──────┐
                     │  port bus   │
                     └─────────────┘
```

核心状态只有 A 位 PP、A 位 DP、统一内存和实现控制状态。地址运算自然截断为 A 位，不需要越界检查。4位 opcode 的16种编码全部有定义；全零机器字执行 `>0`，自然无副作用。

## 单端口 RAM 实现

最节省逻辑的原型可以让取指和 DP 访问分时：

```text
FETCH     memory[PP] → instruction，PP 自增
EXECUTE   根据 opcode 访问 memory[DP] 或端口
```

仅修改 PP/DP 的指令可以少用一个数据访问周期。`P`、`D` 需要一次 DP 相对写入，`@` 需要一次 DP 相对读取。使用组合读存储器时，第一版可以统一采用固定两阶段状态机，以换取验证简单；映射到同步读 RAM 时，可以增加等待或写回阶段，规范不要求所有指令具有相同周期数。

## 指针反射数据通路

`P`、`D`、`@` 共用地址计算：

```text
effective_address = DP + operand
```

写入数据选择：

```text
P write_data = zero_extend_W(PP)
D write_data = zero_extend_W(DP)
```

间接跳转：

```text
@ PP = memory[effective_address][A-1:0]
```

它们不增加架构寄存器、栈或异常，只复用现有加法器、内存端口和 PP 写回路径。

## 双端口 RAM 实现

一个端口为 PP 取指，另一个端口为 DP 数据访问。它提高吞吐率，但 RAM 宏、旁路和同址读写规则会增加实现成本。

如果 PP 和 DP 同址，平台必须明确 RAM 的 read-first/write-first 行为，并用旁路逻辑保证与规范一致。

## 当前字缓存

硬件可以缓存 `memory[DP]`：

- 连续 `+ - = , . [ ] ( )` 直接使用缓存；
- DP 移动前写回旧字；
- DP 移动后装入新字；
- PP 取到可能被缓存覆盖的地址时需要旁路。

这能降低单端口 RAM 压力，但不是最小实现的必要条件。

## I/O 总线

核心只需要一个简单逻辑端口接口：

```text
port_address[A-1:0]
write_data[A+3:0]
read_data[A+3:0]
read_enable
write_enable
```

端口编号描述逻辑地址空间，不要求核心内部实现 `2^A` 个物理寄存器。平台可以按需译码，并把端口映射到：

- GPIO；
- UART FIFO；
- PWM、计时器和计数器；
- DAC/ADC；
- 相邻 Cell 的邮箱或 FIFO；
- 随机数、全局时间或游戏环境。

精确时序应用宜使用固定周期非阻塞端口。慢速外设可以在外围保存状态，而不是让核心加入复杂协议。

## 没有停机状态

Cell 自身持续取指。源码 `:*` 由编译器编码为 operand 全一的 `:(N-1)`，是普通相对自循环，不增加硬件指令。硬件可以检测状态固定并暂时门控时钟，但必须允许外部复位、状态写入或平台事件重新提供执行周期。

外部调试可通过执行使能实现：

```text
enable = 0    保持状态
enable = 1    执行
```

这不需要 HALT、BREAK 或 PAUSED opcode。

## 网页速率与硬件时钟

网页模拟器中的速度单位是 IPS（每秒完成的指令数），不是硬件时钟频率。当前 Logisim 两相原型中，每条指令依次经历 FETCH 和 EXEC，因此在不计等待状态时：

```text
硬件时钟频率 = 2 × 指令执行速率
```

例如网页目标 `4096 IPS` 对应理想情况下约 `8192 Hz` 的两相硬件时钟。网页显示的实测 IPS 会受浏览器调度、内存视图刷新和 I/O 日志影响，不能视为实时保证。

## 多 Cell 阵列

最自然的扩展是每个 Cell 拥有本地内存，通过端口交换消息：

```text
        North
          │
West ── Cell ── East
          │
        South
```

避免全局共享内存可以省去缓存一致性、锁和大规模交叉开关。实现可以采用：

- 同步二维 Mesh；
- GALS/异步邻居网络；
- Tile 内共享执行器、Tile 间消息网络；
- 一个物理核心分时模拟许多逻辑 Cell。

完整管理层是平台功能，可负责程序装载、复位、外部暂停、快照和端口路由，但单个 Cell 不依赖管理层才能持续执行。

## 面积直觉

每个 Cell 的本地存储为：

```text
2^A × (A+4) bit
```

网页定义的处理器家族具有以下逻辑存储规模：

|   A | 内存字数 | 字宽 W | 总存储位数 |
| --: | -------: | -----: | ---------: |
|   4 |       16 |      8 |        128 |
|   5 |       32 |      9 |        288 |
|   6 |       64 |     10 |        640 |
|   7 |      128 |     11 |       1408 |
|   8 |      256 |     12 |       3072 |
|  10 |     1024 |     14 |      14336 |
|  12 |     4096 |     16 |      65536 |

`CM-4+5` 的完整存储只有 `CM-4+8` 的约 9.4%，很适合作为 Logisim 或沙盒游戏中的完整指令集原型。非标准字宽可以映射到更宽的 FPGA RAM 宏；大规模阵列中，SRAM 和互连仍很可能比 PP、DP、ALU 与4→16译码器占用更多资源。
