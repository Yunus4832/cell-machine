# Cell Machine 0.0.1 规范

本文定义 Cell Machine 的参数化架构、紧凑机器编码和源码格式。除非特别说明，数字均为十六进制。

## 1. 架构参数

每台机器由地址位宽 `A` 定义：

```text
opcode 位宽       O = 4
operand 位宽      A
PP / DP 位宽      A
地址数量          N = 2^A
机器字/Cell 位宽  W = A + 4
```

因此机器组成一个保持相同指令语义的规格族：

| 型号      |   A |   W |      统一内存 |
| --------- | --: | --: | ------------: |
| `CM-4+4`  |   4 |   8 |    16 × 8 bit |
| `CM-4+5`  |   5 |   9 |    32 × 9 bit |
| `CM-4+6`  |   6 |  10 |   64 × 10 bit |
| `CM-4+7`  |   7 |  11 |  128 × 11 bit |
| `CM-4+8`  |   8 |  12 |  256 × 12 bit |
| `CM-4+10` |  10 |  14 | 1024 × 14 bit |
| `CM-4+12` |  12 |  16 | 4096 × 16 bit |

实现可以支持其他正整数 A；参考网页支持 `4、5、6、7、8、10、12`。一个 operand 始终覆盖完整地址空间。

## 2. 机器状态

```text
memory[N]    N 个 W 位统一内存字
PP           A 位程序指针
DP           A 位数据指针
```

核心通过 A 位端口地址和 W 位数据接口与平台交互，因此具有 `N` 个逻辑端口编号；端口背后的寄存器、队列、设备及其状态属于平台，不是 Cell Machine 的核心架构状态。

复位状态：

```text
PP = 0
DP = 0
```

程序装载、内存初值和执行周期由宿主平台提供。网页参考实现编译时清零内存并从地址零顺序装入程序。

## 3. 机器字与 opcode

每个统一内存字同时可以是数据或一条完整指令：

```text
W-1        A A-1                  0
+------------+---------------------+
| opcode: 4  | operand: A          |
+------------+---------------------+
```

源码符号只服务于人类书写；编译器把它映射到紧凑 opcode：

| opcode | 符号 | opcode | 符号 |
| -----: | :--: | -----: | :--: |
|    `0` | `>`  |    `8` | `)`  |
|    `1` | `<`  |    `9` | `:`  |
|    `2` | `+`  |    `A` | `;`  |
|    `3` | `-`  |    `B` | `P`  |
|    `4` | `=`  |    `C` | `D`  |
|    `5` | `[`  |    `D` | `@`  |
|    `6` | `]`  |    `E` | `,`  |
|    `7` | `(`  |    `F` | `.`  |

所有 4 位 opcode 都有定义。全零机器字编码为 `>0`，其效果是 `DP ← DP + 0`，因此自然充当 NOP。核心没有 ASCII 机器编码。

例如在 `CM-4+8` 中：

```text
>80 = 0x080
;10 = 0xA10
```

在 `CM-4+12` 中，同样的参数值编译为：

```text
>080 = 0x0080
;010 = 0xA010
```

## 4. 取指

每条指令的架构执行顺序：

```text
instruction ← memory[PP]
PP ← PP + 1 mod N
执行 instruction
```

控制流参数都基于已经自增的 PP。

## 5. 数据和指针指令

| 指令 | 语义                                                 |
| ---- | ---------------------------------------------------- |
| `>n` | `DP ← DP + n mod N`                                  |
| `<n` | `DP ← DP - n mod N`                                  |
| `+n` | `memory[DP] ← memory[DP] + zero_extend_W(n) mod 2^W` |
| `-n` | `memory[DP] ← memory[DP] - zero_extend_W(n) mod 2^W` |
| `=n` | `memory[DP] ← zero_extend_W(n)`                      |

`> < + -` 省略参数时默认使用数值一；`=` 省略参数时默认使用零。

## 6. 相对控制流

| 指令 | 语义                                         |
| ---- | -------------------------------------------- |
| `[n` | 若 `memory[DP] == 0`，则 `PP ← PP + n mod N` |
| `]n` | 若 `memory[DP] != 0`，则 `PP ← PP + n mod N` |
| `:n` | `PP ← PP + n mod N`                          |

无参数 `[` 与 `]` 由编译器配对。若地址分别为 `L`、`R`：

```text
memory[L].operand = R - L mod N
memory[R].operand = L - R mod N
```

配对和偏移计算只存在于编译阶段；硬件不扫描内存，也不维护括号栈。固定点自循环使用可移植语法糖：

```text
:*
```

编译器把 `*` 展开为目标规格的 A 位全一 operand，即 `N-1`。例如 `A=4/5/8/12` 时，`:*` 分别编码为 `:F`、`:1F`、`:FF`、`:FFF`，而源码无需感知地址位宽。`*` 是通用 operand 常量，不是新增指令；它也可以用于其他带参数指令。

## 7. 绝对控制流

| 指令 | 语义                              |
| ---- | --------------------------------- |
| `(n` | 若 `memory[DP] == 0`，则 `PP ← n` |
| `)n` | 若 `memory[DP] != 0`，则 `PP ← n` |
| `;n` | `PP ← n`                          |

无参数 `(` 与 `)` 由编译器配对：

```text
memory[L].operand = R + 1 mod N
memory[R].operand = L + 1 mod N
```

显式参数的 `[]()` 是独立条件跳转，不参与配对。无参数形式必须同类型正确嵌套；不得用一个显式参数括号关闭无参数括号。

## 8. 指针反射与间接执行

三条指令共用：

```text
address = DP + n mod N
```

| 指令 | 语义                                  |
| ---- | ------------------------------------- |
| `Pn` | `memory[address] ← zero_extend_W(PP)` |
| `Dn` | `memory[address] ← zero_extend_W(DP)` |
| `@n` | `PP ← low_A(memory[address])`         |

它们省略参数时都使用零。`P` 读取取指自增后的 PP，因此保存的是下一条指令地址。`P`、`D` 写入完整 W 位字并将高 4 位清零；`@` 只读取目标字的低 A 位。

## 9. I/O

| 指令 | 语义                          |
| ---- | ----------------------------- |
| `,n` | `memory[DP] ← input(port[n])` |
| `.n` | `output(port[n], memory[DP])` |

端口号为完整 A 位 operand，端口数据宽度为 W。协议、阻塞行为和物理连接属于平台规范。

网页平台规定端口零是字符流，输入为空返回零；其余端口是 W 位寄存器式数值端口。字符输出只使用 Cell 的低 8 位。

## 10. 持续性

核心没有 HALT、BREAK、程序末尾、地址异常或非法 opcode。PP、DP、地址和算术按各自位宽自然环绕。程序可以进入状态不再变化的固定点，但只要平台继续提供执行周期，取指与执行仍然持续。宿主可以暂停、单步、复位或修改状态，但这些不是 Cell 指令。

## 11. 源码格式

有效指令符号：

```text
> < + - = [ ] ( ) : ; P D @ , .
```

参数使用一至 `ceil(A/4)` 位十六进制数，可直接跟随 opcode，也可先出现空格或制表符；省略的高位视为零。`*` 可以代替十六进制参数，表示目标规格的 A 位全一常量：

```text
A=4:   >8
A=8:   >80
A=12:  >080
:*
```

参考编译器也接受 `0x80` 形式。参数由 opcode 后连续的十六进制字符组成并采用最长匹配，因此紧邻参数的 `D` 可能被视为十六进制数位；此时应使用空白分隔下一条 `D` 指令。超过目标 A 位范围是编译错误；例如 `A=5` 虽以两位十六进制书写，但最大值只能是 `1F`。完全省略参数时使用各指令规定的默认值。

`#` 开始注释直到行末。其他非指令字符被忽略，但说明文字应放在注释中，避免其中包含指令符号。

## 12. 编译器职责与错误

编译器只承担机器语义所需的机械工作：

1. 将 16 个源码符号映射为 4 位 opcode；
2. 解析并检查 A 位 operand；
3. 将 `*` 展开为目标规格的全一 operand；
4. 填入省略参数的默认值；
5. 匹配无参数 `[]()` 并按 N 计算偏移或绝对地址；
6. 检查程序不超过 N 个机器字。

它不提供标签、变量、宏、函数、类型或隐藏的多指令展开。编译错误属于工具状态，不属于 Cell 的运行时状态。

## 13. 大型程序与可移植性

增加 A 同时扩大程序、数据和端口空间，因此较大型号可以承载更长程序。源码在满足以下条件时可跨规格重新编译：

- 所有显式地址和参数可由目标 A 表示；
- 编译后的程序不超过 `2^A` 个机器字；
- 程序没有依赖特定地址宽度的环绕结果；
- I/O 平台提供所使用的端口。

需要表达目标位宽的全一 operand 时，应优先使用 `*`，而不是在源码中写死 `F`、`FF` 或 `FFF`。

不同 A 的机器字宽度不同，机器码二进制不要求相互兼容；源码和 16 条指令语义才是处理器家族的稳定边界。

## 14. 实现自由

规范定义可观察状态变化，不强制周期数或物理存储形态。实现可以将非标准逻辑字宽映射到更宽的 RAM 宏，也可以采用单端口多周期、双端口、DP 字缓存、固定点时钟门控或多个逻辑 Cell 分时共享执行单元。优化不得改变架构结果。
